# Blobattle — AI coding rules

**Asked to install, host or update the game rather than develop it?** Follow `IA.md` step by step
and stop reading here: the rules below are for changing the code.

## Project Context

Blobattle is a **turn-based artillery game** (a Worms-like with cats): 2 to 8 teams on a procedurally
generated, destructible map rendered in voxels (the cats are drawn as jelly voxel blobs), bazooka
and grenade, bots filling any seat no human takes. It is
played **on phones first**, landscape, through a link served over a Cloudflare tunnel, and as an
Android APK; iOS and Steam come later.

The stack is **Lua end to end**: a **Defold** client, a **Nakama** server using its **Lua runtime**,
and one **pure-Lua simulation** in `shared/` executed unchanged by both. See
`docs/adr-001-defold-lua.md` for why.

Two properties dominate every design decision:

- **One simulation, bit-for-bit deterministic.** The server is the authority; clients replay the
  same inputs at the same ticks and must reach the same state. A client never decides an outcome.
- **The phone is the target, not an adaptation.** Everything is playable with two thumbs in
  landscape on a mid-range phone. A screen that fails at 844×390 is not done.

Read `SPEC.md` before implementing anything. Architecture decisions are numbered `D-01`…`D-15`
there; cite them in commits and reviews. A decision is never contradicted in code — it is rewritten
in the spec first.

## Repository Map

| path | what it owns | may use |
|---|---|---|
| `shared/sim/` | the rules: map, cats, projectiles, weapons, turns, checksum, snapshot | `shared/` only |
| `shared/bots/` | the bot brain: candidate search, scoring, pacing | `shared/sim/` |
| `shared/protocol.lua` | opcodes and message shapes, validation | `shared/` only |
| `server/` | Nakama glue: RPCs, the `room` match handler, bots at runtime | `shared/`, `nk` |
| `client/` | Defold: authority adapters, rendering, camera, input, screens, i18n | `shared/`, Defold APIs |
| `spec/` | busted specs, mirroring the tree file by file; `spec/vectors/` conformance vectors | everything |
| `tools/` | trig table generator, bench, harness (Node), browser journey (Node + CDP) | never shipped |

The dependency direction is one-way: `client/` and `server/` depend on `shared/`; `shared/` depends on
nothing. `server/` and `client/` never depend on each other.

`shared/` lives at the repository root and is reached the same way from both sides:
`require "shared.sim.world"`. Nakama mounts it read-only as `modules/shared`; the Defold project in
`client/` sees it through the committed symlink `client/shared → ../shared`, which `bob.jar` follows.
**Nakama executes every `.lua` file in its modules directory at startup**, so a module under
`shared/` (or `spec/vectors/`) defines and returns its table and does nothing else when loaded.

`docs/sonde/` holds the pre-spec feasibility probe: measurements and reference code for the dynamic
terrain texture, nakama-defold and CDP. `docs/sonde-voxel/` holds the voxel rendering prototype that
settled Q-04: chunked terrain meshing, jelly blobs, measurements. Both are reference, not product
code — never `require` them.

## The Determinism Contract (D-02)

This is the rule that makes the whole architecture work. It applies to **every file under
`shared/`**, and it is enforced by a spec that reads the sources.

- **Integers only.** Positions and velocities are fixed-point, `FP = 256` units per art pixel. No
  decimal literal (`0.5`, `1e-3`) anywhere in `shared/`.
- **Arithmetic through `shared/sim/fixed.lua`**: `fixed.div` (floor division, defined for
  negatives), `fixed.mod`, `fixed.isqrt`, `fixed.clamp`. The operators `/`, `%` and `^` appear in
  `fixed.lua` and nowhere else in `shared/`.
- **Globals are a whitelist**, kept in `spec/support/determinism.lua`: anything outside it —
  including a field of `math`, `string` or `table` — fails the suite. Widening the whitelist is a
  spec change, not a convenience.
- **Trigonometry through the committed table** `shared/sim/trig.lua` (`ANGLES = 1024`,
  `trig.SCALE = 16384`). It is generated by `tools/gen_trig.lua` (`make trig`) and never
  recomputed at runtime.
- **Oriented quantities round symmetrically**: a trig-decomposed velocity or a push direction goes
  through `fixed.round_div` (half away from zero), so a shot to the left mirrors the same shot to
  the right. Everything else floors with `fixed.div`.
- **Forbidden in `shared/`**: `math.sin`, `math.cos`, `math.tan`, `math.atan`, `math.atan2`,
  `math.pow`, `math.exp`, `math.log`, `math.sqrt`, `math.random`, `math.randomseed`, `os.*`, `io.*`,
  `pairs`, `next`, `bit`, `tostring`/`string.format` on numbers, any engine global.
- **Iterate arrays only**, with `ipairs` or a numeric `for`. Arrays never have holes: remove with
  `table.remove` or rebuild. `table.sort` only with a comparator that breaks every tie by id.
- **Magnitudes stay under 2^50.** Bounds live in `shared/sim/rules.lua` and a spec checks them.
- **Randomness comes from `shared/sim/rng.lua`** (Park–Miller, four independent streams: `map`,
  `sim`, `bots`, `names`). A draw from one stream never shifts another.
- **No clock.** Time is the tick counter, 30 per second.

If a feature seems to need a float, a trig call or a hash-map iteration, it does not: find the
integer formulation, or stop and ask.

## Lua Style

- **Every module is a local table returned at the end.** No globals, ever — luacheck runs with
  `allow_defined_top = false` and a closed globals list per directory.
- `local` for everything; cache hot library functions at the top of hot modules
  (`local floor = math.floor`).
- **Guard clauses over nested conditionals.** Return early; three levels of indentation is the
  ceiling.
- **Named fields over positional arguments** for a public function (a module field) with more than
  three parameters or any boolean: `explosion.apply(env, { x = x, y = y, spec = spec })`, never
  `explosion.apply(env, x, y, 12, 16, 50, true)`. The exceptions are the hot-loop primitives, where a
  table per call would be an allocation per cell or per tick: `terrain.get`, `terrain.solid`,
  `terrain.set`, `terrain.carve`, `cat.box_free`, `cat.supported`, `cat.contains`, `cat.step`,
  `projectile.step`. Local helpers are free.
- **Records are plain tables with a fixed set of fields**, created by one constructor per record
  type (`cat.new`, `projectile.new`). Adding a field means updating the constructor, the checksum
  (`world.checksum`) and the snapshot codec in the same commit.
- **Expected failures return `nil, "reason"`**, with a specific reason string
  (`nil, "room_not_found"`, never `nil, "error"`). `error()` is for programmer mistakes and broken
  invariants only.
- **StyLua** formats everything (`stylua.toml` is the rule; disagreements are settled by editing it).
  **luacheck** must be silent; no inline `-- luacheck: ignore` without a line in `.luacheckrc`
  explaining the external constraint.

## Architecture Patterns

### The simulation

- `world.step(world, inputs)` advances exactly one tick and returns the ordered event list (SPEC
  §5.8). It is the only entry point that mutates a world.
- The turn machine (SPEC §5.6) is a **transition table**; a transition not in the table raises.
- Everything tunable lives in `shared/sim/rules.lua`, never as a literal in the module that uses it.
- Map generation takes a seed and settings and returns a world; it reads nothing else.

### Weapons (D-05)

A weapon is **data plus optional hooks** in `shared/sim/weapons/<id>.lua`, registered in
`shared/sim/weapons/registry.lua` (not `init.lua`: Nakama names a module by its path and never
resolves a directory to `init.lua`). Hooks change the world **only through the `EffectApi`** the simulation
hands them. Nothing in the simulation core names a weapon id. Adding a weapon is: module, registry
line, `en` strings, icon — and the shared contract spec must pass without being edited.

### Bots (D-06)

A bot is a player without hands: it reads the public world state and emits the same inputs as a
human, through the same path. Its search evaluates candidates on the **current terrain, read-only**,
never on a mutated copy of the world. Its work is split into bounded slices (`N` candidates per
call). Online, bots run only on the server.

### The server

- The `room` match handler owns the phases `lobby` → `playing` → `ended` (D-07). Phase logic lives
  in one module per phase; the handler dispatches.
- **Every client message is validated before it becomes an input** (D-14): shape via
  `shared/protocol.lua`, bounds, sender, size, rate. A rejected message is dropped and counted,
  never applied, never logged with its content.
- The server broadcasts **tick-stamped inputs**, never world state, except in a snapshot (D-03).
- `nk` is touched only in `server/`. Anything that can be expressed without `nk` belongs in `shared/`.

### The client

- **One seam: the authority** (SPEC §7.1). `LocalAuthority` and `NakamaAuthority` implement the same
  interface; nothing else in the client knows which one is plugged in.
- The client **never advances the simulation past the last tick the authority confirmed**, and
  renders by interpolating between the last two simulated states.
- Aiming is local (D-04): angle and power are quantized to the integers of SPEC §5.1 **before**
  leaving the input layer.
- Scenes are real Defold files (`.collection`, `.go`, `.gui`) — no UI built procedurally in code
  beyond what data demands (a list of seats, a weapon grid).
- Screen composition is designed for **844×390 landscape first**, then checked at 1280×720 and on
  desktop; menus are also checked at 390×844 portrait.
- No sentence in code or data (D-11): every visible string comes from the catalogue by id (English
  only in V0; names are never translated).
- Nothing that exists only on screen (voxel depth, debris, blob squash) feeds back into the sim (D-09).

## Code Quality Standards

### Comments & Documentation

- **All comments, names and code documentation in English.** `SPEC.md`, `V0.md`, `docs/` and commit
  messages are in French.
- **No justification or narration comments.** Rationale belongs in commit messages and `docs/`.
  Prefer code that does not need explaining.
- **A comment is warranted for one thing only**: a non-obvious external constraint —
  `-- gopher-lua has no bit library` earns its place; `-- move the cat` does not.

### Testing

- **busted**; `spec/` mirrors the tree file by file. The `shared/` suite runs **under both LuaJIT and
  Lua 5.1**; a spec that passes under one only is a failure.
- **Tests first, watched failing.** A test written after the code passes on the first run, which
  proves nothing.
- **Tests make the world move the way the game would.** A cat test drives inputs through
  `world.step`, not by writing `cat.x`. A frozen world makes tests pass that prove nothing.
- **Hand-built terrains** (`spec/support/terrains.lua`: flat, stairs, cliff, one-pixel wall, well)
  for physics specs; generated maps only for generation specs and the bench.
- **Minimal mocking — only at the seams**: `nk` on the server, the authority on the client. The
  simulation has no seam and is never mocked.
- **Conformance vectors** (`spec/vectors/`) are written once physics is stable; changing an expected
  checksum needs a commit that says why.
- Test descriptions carry the component emoji: `it("💥 carves exactly the cells inside the radius")`.

### Logging (server)

- JSON logs from Nakama; every application line carries the room code, phase and tick.
- **One emoji per component**: 🏠 room · 🎮 game · 🤖 bot · 🔁 reconnect · 🧮 checksum · 🚫 refusal ·
  💥 explosion (debug only).
- Levels: `info` for lifecycle (room created, game started, game ended), `debug` per tick, `warn` for a
  checksum divergence or a refused message burst, `error` for a broken invariant.
- **Never log** a message payload, a device id, or anything a player typed except their nickname.

### Performance

- A simulation tick stays under 2 ms in LuaJIT on a mid-range phone; after a crater, the terrain
  rebuild never takes more than 4 ms in one frame and finishes before the explosion flash ends.
  Measure before optimizing, and write the measurement in the commit.
- No per-tick allocation in hot loops (`world.step`, projectile integration, rendering): reuse tables.
- The terrain mesh is rebuilt **only for the rows and columns a crater touches**, in per-frame
  slices; rebuilding a whole chunk or the whole map per crater is a defect.

## Security & Privacy

- **The server trusts no client** (D-14). Validate, bound, rate-limit, drop.
- **Nothing personal** (D-15): a device id, a nickname, a team name and its members' names. No
  analytics, no IP in application logs.
- The tunnel exposes only the web build and the Nakama API/socket; the console stays on `127.0.0.1`.
- Secrets (`.env`, tunnel credentials, the Android keystore) are never committed; `.env.example` is.

## Anti-Patterns to Avoid

- **Never put a float, a trig call, `pairs` or a clock in `shared/`.**
- **Never let the client decide an outcome online** — it recomputes, it does not conclude.
- **Never send world state where tick-stamped inputs suffice.**
- **Never mutate the world outside `world.step`**, and never from a weapon hook except through the
  `EffectApi`.
- **Never let a bot read what a human cannot see**, nor act through a path a human cannot use.
- **Never rebuild the whole terrain mesh for one crater.**
- **Never hard-code a tunable** outside `shared/sim/rules.lua`.
- **Never write a visible sentence in code or data** — ids and catalogues.
- **Never add a library the spec does not name** without writing it in `SPEC.md` first.
- **No justification or narration comments.**

## Code Review Checklist

### Before committing

- [ ] Test written first, watched failing, now green under LuaJIT **and** Lua 5.1
- [ ] `luacheck` silent, `stylua --check` clean
- [ ] Nothing in `shared/` breaks D-01 or D-02 (the specs say so; read the diff anyway)
- [ ] New record field added to its constructor, the checksum and the snapshot codec together
- [ ] New tunable lives in `shared/sim/rules.lua` with its bounds
- [ ] Every client message path validates shape, bounds, sender, size and rate
- [ ] Visible strings come from the catalogue
- [ ] Comments in English, none of them narration

### Blobattle-specific

- [ ] Conformance vectors still pass under LuaJIT, Lua 5.1 and Nakama (`make conformance`)
- [ ] The weapon contract spec passes unchanged
- [ ] A bot still reads only public state and emits only regular inputs
- [ ] The client still never simulates past the confirmed tick
- [ ] The screen still works at 844×390 landscape with thumbs
- [ ] The spec was updated first if a numbered decision changed
